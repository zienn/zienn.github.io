1. 什么是 Agent 沙箱，为什么需要

Agent 沙箱是给 AI Agent 的“工具调用”（执行代码、shell 命令、浏览器、文件读写等）提供的受限执行环境。模型输出的代码本质上是不可信代码：它可能有 bug、可能被提示注入（prompt injection）操纵，也可能来自恶意用户。

🧪 代码执行隔离

防止 rm -rf /、fork 炸弹、提权、逃逸到宿主机或其他租户。

📁 文件系统

每个会话独立工作目录；宿主只读或不可见；凭据（~/.ssh、云 token）不可访问。

🌐 网络

默认拒绝出网，或只允许经代理访问白名单域名，防数据外泄和攻击内网（如云元数据 169.254.169.254）。

📊 资源限制

CPU、内存、PID 数、磁盘、运行时长都要有上限，避免一个会话拖垮整台机器。
💡 威胁模型决定选型 “本地 CLI 帮自己改代码”和“SaaS 平台运行陌生人提交的代码”是完全不同的威胁模型。前者用 OS 原生沙箱（bubblewrap / Seatbelt）通常就够了；后者通常需要独立内核（gVisor 或 microVM）这一级的隔离。

2. 隔离层级

从弱到强（同时也大致从轻到重）：

① 进程级：namespace + seccomp + Landlock + rlimit/cgroup，共享宿主内核 —— bubblewrap、nsjail、srt、Codex
② 容器：runc + 镜像 + cgroup + 默认 seccomp，共享宿主内核 —— Docker、Podman、Daytona 默认
③ 用户态内核：在用户态重新实现 Linux 系统调用，宿主内核暴露面大幅缩小 —— gVisor（Modal 在用）
④ microVM：KVM 硬件虚拟化，每个沙箱有自己的 guest 内核 —— Firecracker、Kata、libkrun（E2B、microsandbox）
⊕ WASM：语言级 / 字节码级隔离，能力式（capability）权限，启动最快，但只能跑编译成 wasm 的代码 —— Wasmtime、WasmEdge

2.1 进程级：namespace + seccomp

Linux 提供的积木：

  • namespaces：mnt（独立挂载视图）、pid、net（空网络栈）、user（容器内 root ≠ 宿主 root）、ipc、uts、cgroup。
  • seccomp-bpf：系统调用白/黑名单，例如禁止 socket(AF_INET)、ptrace、mount。
  • Landlock：非特权进程也能给自己加文件系统访问规则。
  • cgroup v2 / rlimit：CPU、内存、pids 上限。
  • no_new_privs：禁止通过 setuid 程序提权。
# bubblewrap：只读宿主根目录，仅工作目录可写，断网，独立 PID 命名空间
bwrap \
  --ro-bind /usr /usr --ro-bind /lib /lib --ro-bind /lib64 /lib64 --ro-bind /bin /bin \
  --bind /srv/sessions/s-42/work /work --chdir /work \
  --proc /proc --dev /dev --tmpfs /tmp \
  --unshare-all --die-with-parent --new-session \
  --clearenv --setenv PATH /usr/bin:/bin --setenv HOME /work \
  python3 -c 'print("hello from sandbox")'

OpenAI Codex CLI 和 Anthropic sandbox-runtime（srt）在 Linux 上都是这个思路：Codex 现在默认用 bubblewrap 构造文件系统视图，再在进程内加 PR_SET_NO_NEW_PRIVS 和 seccomp 网络过滤，Landlock 降为可选的旧方案；srt 用 bubblewrap 加网络命名空间，所有出网流量必须经过宿主上的代理（通过 Unix socket 桥接），由代理按域名白名单放行。

2.2 容器

本质上是 2.1 的“打包版”：OCI 镜像 + runc + 默认 seccomp/AppArmor 配置 + cgroup。好处是生态成熟、镜像现成；问题是共享宿主内核，内核漏洞（如 Dirty Pipe、各类 io_uring 漏洞）可以导致逃逸。多租户运行陌生代码时，一般不把普通 runc 容器当作唯一的安全边界。

2.3 用户态内核：gVisor

gVisor 的 runsc 是一个 OCI 运行时。它的 Sentry 在用户态用 Go 实现了大部分 Linux 系统调用，网络栈（netstack）也在用户态；文件访问经 Gofer（或 directfs）代理。平台层可以选 systrap（默认，不需要 KVM）或 kvm。优点：启动接近容器，不需要嵌套虚拟化；代价：syscall 密集型和 IO 密集型负载有额外开销，少数系统调用不兼容。Modal Sandboxes 和 GKE Sandbox 都基于 gVisor。

2.4 microVM：Firecracker / Kata / libkrun

  • Firecracker（AWS Lambda/Fargate 在用）：Rust 编写的极简 VMM，只提供 virtio-net/blk/vsock 等少量设备。官方规格：从 InstanceStart 到 guest /sbin/init 不超过 125ms（1 vCPU / 128MiB、最小内核），每个 VMM 进程的内存开销不超过 5MiB（不含 guest 内存）。支持快照/恢复，生产环境建议用 jailer 包一层（chroot + cgroup + namespace + 降权）。
  • Kata Containers：把 microVM 包装成 OCI 运行时，可在 K8s 中通过 RuntimeClass 使用。底层可选 QEMU、Cloud Hypervisor、Firecracker、Dragonball。
  • libkrun：把 VMM 做成一个库嵌进进程，microsandbox 基于它（Linux KVM / macOS HVF）。

2.5 WebAssembly

Wasm 模块默认什么都不能做，文件、网络、时钟等能力都要通过 WASI 显式授予。Wasmtime 的 pooling allocator 实例化一个小模块约 5µs（官方基准 PR 实测 5.27–5.43µs）。缺点：Agent 常用的 pip install、任意二进制、完整 shell 都跑不了；适合插件、表达式求值、Python-in-Wasm（Pyodide）这类受限场景。

层级隔离边界典型启动密度兼容性适用
进程级宿主内核 + seccomp毫秒级极高完整 Linux 用户态本地 CLI、单租户、可信度较高的 Agent
容器宿主内核约百毫秒到 1 秒高完整单租户、内部工具
gVisor用户态内核约百毫秒到 1 秒高大部分 syscall多租户代码执行（无 KVM 环境）
microVM硬件虚拟化约 100ms 冷启动；快照恢复更快中高完整（独立内核）多租户、强隔离、长会话
WASM运行时 + 能力模型微秒级极高仅限 wasm插件、函数级执行

3. 沙箱生命周期：何时创建、何时销毁

3.1 粒度：按会话 or 按任务

按会话（per-session）

一次对话共用一个沙箱，文件、已装依赖、进程状态在多次工具调用之间保留。Code Interpreter、编码 Agent 常用这种。

按任务 / 按调用（per-task）

每次执行都用全新沙箱，跑完即毁。最安全、无状态残留，适合评测、RL rollout、一次性函数执行。

3.2 关键策略

  • 懒创建（lazy create）：会话开始时不建沙箱，第一次真正发生工具调用时才建。很多对话根本不跑代码，这样能省下大量资源。
  • 空闲 TTL：最后一次活动后 N 分钟没有动作就暂停或销毁；再设一个最长存活时间作为硬上限。
  • 会话结束：用户关闭会话或会话过期时主动销毁，并清理卷、网络、cgroup。
  • 预热池（warm pool）：预先启动 N 个空白沙箱，请求来了直接“认领”，把冷启动挪出关键路径。
  • 快照 / 恢复（snapshot/restore）：把“装好依赖的已启动环境”做成内存加磁盘快照，新沙箱直接从快照恢复。E2B 的“创建”本质上就是恢复一个预启动的快照：内存页通过 userfaultfd 按需加载，根文件系统是写时复制（CoW）。
  • 暂停 / 恢复（pause/resume）：空闲时把整个沙箱状态保存下来，释放 CPU 和内存，有流量时再透明唤醒。E2B、Daytona、k8s agent-sandbox（hibernation）都支持。
  • Fork：从一个运行中的沙箱分叉出多个副本，适合并行探索、RL。

  • Agent Server 保持无状态：会话到沙箱的映射放在外部存储，任何副本都能处理任何会话。
  • Sandbox Manager 负责调度（选节点、做亲和）、配额（每个用户/租户最多几个沙箱）、TTL 和 GC。
  • 节点 Agent（如 E2B 的 orchestrator 加 VM 内的 envd）负责在本机实际创建和执行沙箱，对外暴露 exec / files / pty 等 API。
  • 凭据不进沙箱：由 egress 代理在请求经过时注入 token（microsandbox、srt 都采用类似思路），沙箱里的代码拿不到真实密钥。

5. 一个 Kubernetes Pod 内运行多个沙箱

为什么要这样做？Pod 冷启动（调度、拉镜像、挂卷、CNI）通常要秒级，而且每个 Pod 都占用 API Server、etcd 和 kubelet 的资源。会话量一旦到了上万，一个会话一个 Pod 的成本和延迟都很难接受。做法是让一个“沙箱宿主 Pod”（大规格、长期运行）在内部按会话再起一层隔离。

5.1 方案 A：每个会话一个 bubblewrap / nsjail 进程

最轻量的方案，毫秒级启动，单个 Pod 可承载数百个沙箱。隔离强度属于进程级，适合单租户或可信度较高的场景，也可以叠加在 gVisor Pod（runtimeClassName: gvisor）之上形成两层防护。

⚠️ Pod 内创建 namespace 需要权限 容器运行时默认的 seccomp/AppArmor 配置通常会拦截非特权的 unshare(CLONE_NEWUSER) 和 mount，被 mask 的 /proc 也会导致 --proc 失败。常见做法： ① 开启 K8s 用户命名空间（hostUsers: false，v1.36 已 GA），再授予 SYS_ADMIN，这个能力只在 Pod 自己的 userns 内有效，比 privileged 安全得多； ② 配合 procMount: Unmasked（需要 userns）和自定义 seccomp profile； ③ 退而求其次用 privileged: true。不论哪种，都应该叠加 gVisor/Kata 运行时，或者让沙箱节点专用并打污点隔离。

下面是节点 Agent 的核心逻辑（Python）：按会话创建工作目录和 cgroup，用 bwrap 执行命令，记录活跃时间，后台按 TTL 回收。

# agentd/sandbox.py —— 单 Pod 多沙箱管理器（bubblewrap + cgroup v2）
import asyncio, os, shutil, time, uuid
from dataclasses import dataclass, field
from pathlib import Path

SESSIONS = Path("/sessions")
CGROOT = Path("/sys/fs/cgroup/sandboxes")   # 需要 cgroup 可写（cgroupns + 委派）
IDLE_TTL = 15 * 60          # 空闲 15 分钟回收
MAX_LIFETIME = 4 * 3600     # 最长存活 4 小时
MAX_SANDBOXES = 200         # 单 Pod 容量上限


@dataclass
class Sandbox:
    id: str
    session_id: str
    workdir: Path
    cgroup: Path
    created: float = field(default_factory=time.time)
    last_active: float = field(default_factory=time.time)
    lock: asyncio.Lock = field(default_factory=asyncio.Lock)


class SandboxManager:
    def __init__(self) -> None:
        self.by_session: dict[str, Sandbox] = {}
        CGROOT.mkdir(parents=True, exist_ok=True)
        # 在父 cgroup 打开子控制器，子 cgroup 才能设置 cpu/memory/pids 限制
        (CGROOT / "cgroup.subtree_control").write_text("+cpu +memory +pids")

    async def get_or_create(self, session_id: str) -> Sandbox:
        """懒创建：第一次工具调用时才真正建沙箱。"""
        sb = self.by_session.get(session_id)
        if sb:
            return sb
        if len(self.by_session) >= MAX_SANDBOXES:
            raise RuntimeError("pod at capacity")  # 让 Manager 调度到别的 Pod
        sid = f"sb-{uuid.uuid4().hex[:12]}"
        workdir = SESSIONS / sid / "work"
        workdir.mkdir(parents=True)
        cg = CGROOT / sid
        cg.mkdir()
        (cg / "memory.max").write_text(str(2 * 1024**3))   # 2 GiB
        (cg / "memory.swap.max").write_text("0")
        (cg / "cpu.max").write_text("200000 100000")       # 2 核
        (cg / "pids.max").write_text("256")                # 防 fork 炸弹
        sb = Sandbox(sid, session_id, workdir, cg)
        self.by_session[session_id] = sb
        return sb

    def _bwrap_argv(self, sb: Sandbox, cmd: list[str], network: bool) -> list[str]:
        argv = [
            "bwrap",
            "--ro-bind", "/usr", "/usr",
            "--symlink", "usr/bin", "/bin", "--symlink", "usr/lib", "/lib",
            "--symlink", "usr/lib64", "/lib64",
            "--ro-bind", "/etc/ssl", "/etc/ssl",
            "--bind", str(sb.workdir), "/work", "--chdir", "/work",
            "--proc", "/proc", "--dev", "/dev", "--tmpfs", "/tmp",
            "--unshare-user", "--unshare-pid", "--unshare-ipc", "--unshare-uts",
            "--unshare-cgroup-try",
            "--die-with-parent", "--new-session",
            "--clearenv", "--setenv", "HOME", "/work",
            "--setenv", "PATH", "/usr/local/bin:/usr/bin",
        ]
        if not network:
            argv.append("--unshare-net")   # 空网络栈；需要出网则走 egress 代理
        return argv + ["--"] + cmd

    async def exec(self, session_id: str, cmd: list[str],
                   timeout: float = 60, network: bool = False) -> dict:
        sb = await self.get_or_create(session_id)
        async with sb.lock:                         # 同一会话串行执行
            sb.last_active = time.time()

            def enter_cgroup() -> None:              # 在子进程 exec 之前加入 cgroup
                (sb.cgroup / "cgroup.procs").write_text(str(os.getpid()))

            proc = await asyncio.create_subprocess_exec(
                *self._bwrap_argv(sb, cmd, network),
                stdout=asyncio.subprocess.PIPE, stderr=asyncio.subprocess.PIPE,
                preexec_fn=enter_cgroup,
            )
            try:
                out, err = await asyncio.wait_for(proc.communicate(), timeout)
            except asyncio.TimeoutError:
                (sb.cgroup / "cgroup.kill").write_text("1")   # 杀掉整个进程树
                await proc.wait()
                return {"exit_code": -9, "stdout": "", "stderr": "timeout"}
            finally:
                sb.last_active = time.time()
            return {"exit_code": proc.returncode,
                    "stdout": out.decode(errors="replace")[-100_000:],
                    "stderr": err.decode(errors="replace")[-100_000:]}

    async def destroy(self, session_id: str) -> None:
        sb = self.by_session.pop(session_id, None)
        if not sb:
            return
        (sb.cgroup / "cgroup.kill").write_text("1")
        for _ in range(50):                          # 等 cgroup 清空再删除
            if not (sb.cgroup / "cgroup.procs").read_text().strip():
                break
            await asyncio.sleep(0.1)
        sb.cgroup.rmdir()
        shutil.rmtree(sb.workdir.parent, ignore_errors=True)

    async def gc_loop(self) -> None:
        """后台 GC：空闲超时 / 超过最长存活一律回收。"""
        while True:
            now = time.time()
            for sid, sb in list(self.by_session.items()):
                if now - sb.last_active > IDLE_TTL or now - sb.created > MAX_LIFETIME:
                    if not sb.lock.locked():
                        await self.destroy(sid)
            await asyncio.sleep(30)
nsjail 等价写法nsjail 把 namespace、cgroup、rlimit、seccomp（Kafel 策略语言）集中到一个配置里，适合需要精细 syscall 策略的场景： nsjail -Mo --chroot / --user 99999 --group 99999 --cgroup_mem_max 2147483648 --cgroup_pids_max 256 --time_limit 60 --disable_proc -- /usr/bin/python3 main.py

5.2 方案 B：在 Pod 内调用 runsc 起多个 gVisor 沙箱

如果节点上没有配置 gVisor 的 RuntimeClass，也可以在 Pod 里直接运行 runsc，每个会话一个 OCI bundle。不需要 KVM，默认 systrap 平台即可。不过 runsc 本身也要创建 namespace 和挂载，所以同样需要 5.1 中提到的权限，实践中通常是 privileged 或 userns + SYS_ADMIN。官方的 rootless 模式（runsc --rootless do）限制较多：不支持 runsc create、不支持 save/restore、不能用 netstack。

// runscpool.go —— 在 Pod 内为每个会话起一个 gVisor 沙箱（OCI bundle + runsc run）
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"os"
	"os/exec"
	"path/filepath"
	"time"
)

const root = "/sessions"

type ociSpec map[string]any

func makeSpec(workdir string) ociSpec {
	return ociSpec{
		"ociVersion": "1.0.2",
		"process": map[string]any{
			"args": []string{"sleep", "infinity"}, // 常驻 init，后续用 runsc exec 执行命令
			"cwd":  "/work",
			"env":  []string{"PATH=/usr/local/bin:/usr/bin:/bin", "HOME=/work"},
			"user": map[string]int{"uid": 1000, "gid": 1000},
			"rlimits": []map[string]any{
				{"type": "RLIMIT_NOFILE", "hard": 4096, "soft": 4096},
			},
		},
		"root": map[string]any{"path": "/opt/rootfs", "readonly": true}, // 共享只读 rootfs
		"mounts": []map[string]any{
			{"destination": "/work", "type": "bind", "source": workdir, "options": []string{"rbind", "rw"}},
			{"destination": "/tmp", "type": "tmpfs", "source": "tmpfs"},
			{"destination": "/proc", "type": "proc", "source": "proc"},
		},
		"linux": map[string]any{
			"namespaces": []map[string]string{
				{"type": "pid"}, {"type": "network"}, {"type": "ipc"}, {"type": "uts"}, {"type": "mount"},
			},
			"resources": map[string]any{
				"memory": map[string]any{"limit": 2 << 30},
				"cpu":    map[string]any{"quota": 200000, "period": 100000},
				"pids":   map[string]any{"limit": 256},
			},
		},
	}
}

// Create 起一个新的 gVisor 沙箱；--network=none 表示完全断网。
func Create(ctx context.Context, id string) error {
	bundle := filepath.Join(root, id)
	work := filepath.Join(bundle, "work")
	if err := os.MkdirAll(work, 0o755); err != nil {
		return err
	}
	spec, _ := json.Marshal(makeSpec(work))
	if err := os.WriteFile(filepath.Join(bundle, "config.json"), spec, 0o644); err != nil {
		return err
	}
	cmd := exec.CommandContext(ctx, "runsc",
		"--root=/run/runsc", "--platform=systrap", "--network=none",
		"run", "--detach", "--bundle", bundle, id)
	if out, err := cmd.CombinedOutput(); err != nil {
		return fmt.Errorf("runsc run: %v: %s", err, out)
	}
	return nil
}

// Exec 在已有沙箱中执行一条命令，带超时。
func Exec(id string, timeout time.Duration, args ...string) ([]byte, error) {
	ctx, cancel := context.WithTimeout(context.Background(), timeout)
	defer cancel()
	full := append([]string{"--root=/run/runsc", "exec", "--cwd", "/work", id}, args...)
	return exec.CommandContext(ctx, "runsc", full...).CombinedOutput()
}

// Destroy 强制删除沙箱并清理工作目录。
func Destroy(id string) {
	_ = exec.Command("runsc", "--root=/run/runsc", "delete", "--force", id).Run()
	_ = os.RemoveAll(filepath.Join(root, id))
}

func main() {
	ctx := context.Background()
	if err := Create(ctx, "sb-demo"); err != nil {
		panic(err)
	}
	defer Destroy("sb-demo")
	out, err := Exec("sb-demo", 30*time.Second, "python3", "-c", "import os; print(os.uname())")
	fmt.Println(string(out), err) // uname 中可以看到 gVisor 模拟的内核
}
✅ 更推荐的做法如果能控制节点，在节点上安装 runsc 并注册 RuntimeClass（GKE Sandbox 开箱即用），然后让沙箱宿主 Pod 用 runtimeClassName: gvisor 运行。这样整个 Pod 就在 gVisor 里，Pod 内再用 bwrap 按会话细分（方案 A 叠加 B），不需要 privileged。

5.3 方案 C：特权 Pod + /dev/kvm 运行 Firecracker microVM

隔离最强，每个会话都有独立内核。需要节点支持 KVM：裸金属，或开启了嵌套虚拟化的云主机（GKE、部分 EC2 实例类型等）。Pod 需要访问 /dev/kvm，并且要能创建 TAP 设备（需要 NET_ADMIN）。最简单的是 privileged；更规范的做法是用 device plugin（如 KubeVirt 的 kvm device plugin）申请 devices.kubevirt.io/kvm 资源，再加上 NET_ADMIN。

apiVersion: v1
kind: Pod
metadata:
  name: fc-host-0
  labels: { app: fc-host }
spec:
  nodeSelector: { kvm: "true" }          # 只调度到支持 KVM / 嵌套虚拟化的节点
  automountServiceAccountToken: false
  containers:
  - name: fc-agent
    image: registry.example.com/fc-host:2.0   # 内含 firecracker、jailer、vmlinux、rootfs 模板
    securityContext:
      privileged: true                   # 或者：device plugin 提供 /dev/kvm + capabilities NET_ADMIN
    resources:
      limits: { cpu: "32", memory: 128Gi }
    volumeMounts:
    - { name: kvm, mountPath: /dev/kvm }
    - { name: vms, mountPath: /var/lib/fc }
  volumes:
  - name: kvm
    hostPath: { path: /dev/kvm, type: CharDevice }
  - name: vms
    emptyDir: { medium: "", sizeLimit: 500Gi }

// fcvm.go —— 通过 Firecracker 的 Unix socket REST API 启动一台 microVM（极简版）
package main

import (
	"bytes"
	"context"
	"fmt"
	"net"
	"net/http"
	"os"
	"os/exec"
	"time"
)

func client(sock string) *http.Client {
	return &http.Client{Transport: &http.Transport{
		DialContext: func(ctx context.Context, _, _ string) (net.Conn, error) {
			return (&net.Dialer{}).DialContext(ctx, "unix", sock)
		},
	}}
}

func put(c *http.Client, path, body string) error {
	req, _ := http.NewRequest(http.MethodPut, "http://localhost"+path, bytes.NewBufferString(body))
	req.Header.Set("Content-Type", "application/json")
	resp, err := c.Do(req)
	if err != nil {
		return err
	}
	defer resp.Body.Close()
	if resp.StatusCode >= 300 {
		return fmt.Errorf("PUT %s: %s", path, resp.Status)
	}
	return nil
}

func StartVM(id string) (*exec.Cmd, error) {
	sock := "/var/lib/fc/" + id + ".sock"
	_ = os.Remove(sock)
	// 生产环境应改用 jailer：chroot + cgroup + 独立 uid，再 exec firecracker
	cmd := exec.Command("firecracker", "--api-sock", sock, "--id", id)
	if err := cmd.Start(); err != nil {
		return nil, err
	}
	time.Sleep(50 * time.Millisecond) // 简化：真实代码应轮询 socket 就绪
	c := client(sock)
	steps := []struct{ path, body string }{
		{"/boot-source", `{"kernel_image_path":"/opt/fc/vmlinux","boot_args":"console=ttyS0 reboot=k panic=1 pci=off"}`},
		// 每台 VM 一个 CoW 的 rootfs 副本（如 reflink / overlay / devmapper 快照）
		{"/drives/rootfs", `{"drive_id":"rootfs","path_on_host":"/var/lib/fc/` + id + `.ext4","is_root_device":true,"is_read_only":false}`},
		{"/machine-config", `{"vcpu_count":2,"mem_size_mib":1024}`},
		{"/network-interfaces/eth0", `{"iface_id":"eth0","host_dev_name":"tap-` + id + `"}`},
		{"/vsock", `{"guest_cid":3,"uds_path":"/var/lib/fc/` + id + `.vsock"}`}, // 宿主与 guest agent 通信
		{"/actions", `{"action_type":"InstanceStart"}`},
	}
	for _, s := range steps {
		if err := put(c, s.path, s.body); err != nil {
			_ = cmd.Process.Kill()
			return nil, err
		}
	}
	return cmd, nil
}

func main() {
	vm, err := StartVM("sb-001")
	if err != nil {
		panic(err)
	}
	fmt.Println("microVM started, pid", vm.Process.Pid)
	// 暂停 + 快照：PATCH /vm {"state":"Paused"}，再 PUT /snapshot/create
	// 恢复：新进程 PUT /snapshot/load {"snapshot_path":...,"mem_backend":{...},"resume_vm":true}
}

不想自己拼这些的话，可以用 firecracker-containerd、Kata（kata-fc RuntimeClass）、E2B 开源的 runtime，或者 microsandbox（libkrun，以库的形式嵌入，不需要守护进程）。

5.4 方案 D：Docker-in-Docker / Sysbox / rootless Podman

  • DinD（docker:dind）：需要 privileged: true，等于把节点交出去，不推荐用于不可信代码。
  • Sysbox（Nestybox，2022 年被 Docker 收购）：一个 OCI 运行时（sysbox-runc），让非特权容器也能在里面跑 Docker、systemd 甚至 K8s。它通过用户命名空间和对 /proc、/sys 的虚拟化实现。需要在节点上安装，并通过 RuntimeClass 使用。
  • rootless Podman：Pod 内的非 root 用户运行 podman run。需要 /dev/fuse（fuse-overlayfs）、subuid/subgid 映射，以及能创建 userns 的权限。配合 hostUsers: false 体验最好。
# rootless podman：每个会话一个容器，带资源限制、断网、只读根
podman run -d --name sess-42 \
  --userns=keep-id --network=none --read-only \
  --memory=2g --cpus=2 --pids-limit=256 \
  --tmpfs /tmp:rw,size=512m \
  -v /sessions/s-42/work:/work:Z -w /work \
  --security-opt no-new-privileges --cap-drop=ALL \
  python:3.12-slim sleep infinity
podman exec sess-42 python -c 'print(1+1)'
podman rm -f sess-42      # 回收

维度做法注意
CPU / 内存 / PID每个沙箱一个 cgroup v2 子组：cpu.max、memory.max、pids.max；Pod 本身的 limit 作为总上限Pod 内的 cgroup 默认只读，需要 cgroupns 委派（privileged 或 userns 下以可写方式挂载），否则只能退回 rlimit 或交给 runsc/VM 自己限制

6.1 kubernetes-sigs/agent-sandbox

由 SIG Apps 推动的官方子项目，核心是 Sandbox CRD（agents.x-k8s.io/v1beta1），用来描述“单实例、有状态、身份稳定、可带持久存储”的 Pod，可以理解为 K8s 上的轻量 VM。扩展 CRD（extensions.agents.x-k8s.io/v1beta1）包括 SandboxTemplate、SandboxClaim、SandboxWarmPool。官方文档列出的能力还有休眠与恢复（hibernation）、按时间自动删除（shutdownTime），并兼容 gVisor、Kata 等运行时，同时提供 Python 和 Go SDK。

🔐 安全底线

不可信代码至少要有独立内核这一级（gVisor 或 microVM）；凭据不进沙箱；默认断网，出网走白名单代理；屏蔽元数据地址。

⚡ 延迟

懒创建 + 预热池 + 快照恢复是三板斧；度量以 Ready 为准，而不是 Started。

💰 成本

空闲 TTL 后先暂停（保存快照）再销毁；会话级 CPU/内存配额；高密度场景用一 Pod 多沙箱。

🧹 可靠性

GC + 启动时对账 + 进程树级强杀 + 磁盘配额，防止资源泄漏拖垮节点。
